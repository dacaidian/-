# 运行时效果生命周期设计

> Encoding guard: this document must stay valid UTF-8. If Chinese text becomes unreadable, repair the encoding before editing.

## 为什么需要独立生命周期

一个运行时效果通常至少包含四个不同阶段：

1. 激活：读取施法者、目标、资源和当前规则状态。
2. 生效：把能力写入 `CardStatus`、玩家运行时状态或其他权威模型。
3. 存续：经历刷新、回合切换、控制权变化、死亡结算等事件。
4. 失效：在明确时点撤销能力，并触发必要的派生属性重算与死亡检查。

“当前模式是否开启”只描述激活条件，不等于效果的存续条件。不能因为施法回合结束，就默认删除施法回合中生成的所有效果。甲赫反伤就是典型案例：能力在己方赫子解放时激活，但主要价值发生在随后的敌方回合。

## 配置时必须回答的问题

每个跨时点效果都必须明确以下语义：

- **来源玩家**：谁施加了效果，通常写入 `source_owner_id`。
- **持续时间归属**：按目标玩家、来源玩家还是全局时点计时。
- **失效触发点**：`before_turn_start`、`after_turn_end` 或其他明确事件。
- **持续次数**：`remaining_turns` 每次命中归属时点后如何递减。
- **快照或实时**：激活时锁定数值，还是随来源状态变化持续重算。
- **叠加策略**：叠加、刷新、替换或忽略。
- **死亡与净化**：是否可净化，死亡后是否保留。
- **行动资源**：状态授予的动作在何时恢复次数，失效与行动恢复谁先发生。

如果这些问题没有答案，不应只写一个模糊的“持续一回合”。

## 标准时点模式

### 本回合临时效果

例：野蛮咆哮、尾赫齐发的攻击力 +1。

- `duration_scope: "source_owner"`
- `expires_on_trigger: "after_turn_end"`
- `duration_turns: 1`

适用于只服务当前主动回合、敌方回合不应继续存在的能力。

### 跨敌方回合的响应效果

例：赫子解放产生的甲赫护甲与反伤。

- 激活时生成能力快照。
- `duration_scope: "source_owner"`
- `expires_on_trigger: "before_turn_start"`
- `duration_turns: 1`

效果会完整经历敌方回合，在来源玩家下个回合开始、行动恢复之前失效。

### 目标自身回合计时

例：施加给敌方随从，并要求经历该随从拥有者回合的控制或减益。

- `duration_scope: "target_owner"`
- 根据规则选择 `before_turn_start` 或 `after_turn_end`。

不要用施法者回合替代目标回合，否则双方交替行动时会产生半回合或额外一回合的偏差。

## 快照与实时重算

快照效果在激活时读取所有依赖并固定 payload。赫子解放采用该模式：开启时读取 RC 浓度，生成对应的攻击、护甲、移动、关键字和动作；随后 RC 变化不会重写本次解放。

实时效果应由明确的 aura/passive resolver 持续同步，并在来源失效时撤销。只有规则文案明确表达“只要条件成立”时才应使用实时模式。

不要让普通 `refresh_player()` 同时承担快照效果的创建、重算和删除。刷新函数应满足幂等性：

- 多次调用不会重复叠加同一效果。
- 非激活阶段不会提前删除仍在合法持续期内的状态。
- 已存在的快照不会因无关 HUD、手牌或被动刷新被改写。
- 旧数据迁移可以显式处理，但不能成为常规生命周期。

## 多入口必须共用生命周期

同一种基础能力可能由施法回合、法术牌、随从动作或触发器施加。它们可以拥有不同数值，但不能各自定义冲突的持续时点。

当前赫子能力统一通过 `KagunePowerResolver.configure_status_lifecycle()` 设置生命周期：

- 全局赫子解放使用 `create_kagune_status()`。
- “尾赫齐发”等单独触发入口使用 `ApplyKagunePowerEffect`。
- 两者共用 payload 构造和失效时点。
- 卡牌额外写明“本回合”的独立数值状态仍可在回合结束时移除。

新增入口时，应调用权威 resolver 的公共配置方法，不复制 `duration_scope` 和 trigger 字符串。

## 结算顺序

当前回合切换的关键顺序是：

1. 当前玩家结束回合。
2. 结算 `after_turn_end` 状态与触发器。
3. 推进种族运行时状态。
4. 切换当前玩家。
5. 结算新玩家 `before_turn_start` 状态与触发器。
6. 刷新被动、开始玩家回合并恢复全场行动资源。

因此“下个己方回合开始时失效”的状态应在第 5 步移除，避免它影响新回合行动，同时保证它完整覆盖敌方回合。

状态移除若会降低生命上限、取消免死或恢复控制权，必须继续走 `StatusResolver` 的后处理，不能从 UI 或普通刷新函数直接删除后跳过死亡检查。

## 回归测试矩阵

每个新增跨时点效果至少验证：

- 激活后立即存在且数值正确。
- 同一回合多次刷新不会重复叠加或覆盖快照。
- 来源玩家回合结束后仍按设计存在或消失。
- 对方回合开始和结束不会错误递减来源玩家状态。
- 来源玩家下个回合的指定时点准确失效。
- 失效后攻击、护甲、生命上限、关键字和授予动作全部恢复。
- 多个施加入口得到相同生命周期。
- 控制权变化、变身、死亡、复生和净化符合状态标签约定。
- 到期导致生命归零时，死亡、亡语、复生和补牌链继续完整执行。

不要只断言 `remaining_turns`。测试应调用 `expire_statuses_for_turn_timing()` 或实际回合编排，并验证最终派生状态。

## 实现检查清单

- 生命周期定义是否位于权威规则层，而不是卡牌 UI 或动画层？
- `source_owner_id` 与 `duration_owner_id` 是否正确？
- 使用的是快照还是实时重算，文案与代码是否一致？
- refresh 是否幂等，是否会误删跨回合状态？
- 多个施加入口是否复用同一配置方法？
- 失效时点是否经过敌方完整回合？
- 状态移除是否触发派生属性重算和必要的死亡检查？
- 卡牌描述、架构文档和专项测试是否同步？
